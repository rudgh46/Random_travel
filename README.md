# 오늘의 랜덤 여행 🚌

서울고속버스터미널(경부·영동선)과 센트럴시티(호남선)에서 출발하는
랜덤 여행지를 뽑아주는 웹사이트입니다. 터미널·권역·예산·소요시간을 고르고
**출발!** 을 누르면 안내판이 돌아가다 목적지에서 멈추고, 탑승권 카드에
예상 요금·소요시간·등급·당일치기 여부를 보여줍니다.

목적지가 정해지면 안내판의 지명(또는 **근처 볼거리 보기** 버튼)을 눌러
그 지역의 볼거리를 펼쳐 볼 수 있습니다. 카드를 누르면 네이버 지도 검색으로
이어집니다. 77개 목적지 전체에 대해 내장 데이터로 동작하며 별도 API 키가 필요 없습니다.

**출발일·출발 시각** 을 고르면 승차권에 `8/8(토) 09:00 → 10:37 도착 예정` 이
표시되고, 날씨도 그 날짜 기준으로 바뀝니다. 도착 시각은 내장 소요시간으로
계산한 값이라 실제 배차 시각이 아니며, 그래서 **"예정"으로 표기**합니다.
실제 출발편은 코버스에서 확인하세요. 자정을 넘기면 `익일` 로 표시합니다.

**공유하기** 를 누르면 그 목적지와 출발 일시로 바로 열리는 링크가 만들어집니다
(`?to=강릉&d=2026-08-08&t=09:00`). 모바일에서는 공유 시트가 열리고, 데스크톱에서는 링크가
클립보드에 복사됩니다. 뽑을 때마다 주소창도 결과에 맞춰 갱신되니
새로고침하거나 주소를 복사해도 같은 목적지가 유지됩니다.

필터(터미널·권역·예산·소요시간)는 브라우저에 기억되고, 최근에 뽑은 곳은
잠시 제외해서 같은 목적지가 연달아 나오지 않습니다.

승차권에는 **목적지의 오늘 날씨**(상태·현재기온·최저/최고·강수확률)와
날씨에 맞춘 한 줄 제안이 함께 표시됩니다. [Open-Meteo](https://open-meteo.com) 를
쓰며 **인증키가 필요 없고 CORS가 열려 있어** 프록시 없이 브라우저에서 직접
호출합니다. 강수확률이 60% 이상이면 우산 안내가 붙고, 조회에 실패하면 그 줄만
조용히 숨깁니다.

**비 안 오는 곳만** 을 켜면 **선택한 출발일** 기준으로 강수확률 50% 이상인
목적지를 후보에서 제외합니다. Open-Meteo 는 좌표를 콤마로 이어 붙이면 여러
지점을 한 번에 돌려주므로, 77곳 전체를 **요청 1회**로 받아 걸러냅니다.
날짜를 바꾸면 그 날짜로 다시 조회하고, 조회에 실패하면 토글이 자동으로
해제되고 이유를 표시합니다.

> 날짜 선택 범위가 **오늘 + 15일** 인 것은 Open-Meteo 예보 한계입니다
> (`start_date` 허용 범위). 그 이상은 조회 자체가 거부됩니다.

Netlify에 배포하면 TAGO(공공데이터포털) API로 **오늘 실제 출발편·요금**을
탑승권에 실시간으로 얹습니다. 프록시가 없으면(로컬·GitHub Pages 등)
정적 예상값으로 조용히 동작합니다.

> **TAGO 배차 정보는 오늘·내일까지만 제공됩니다.** 그 이후 날짜를 고르면
> 0편이 돌아오며, 이때 실시간 줄은 숨겨지고 계산값("도착 예정")만 남습니다.
> 프록시나 API 장애 시에도 같은 방식으로 그 줄만 조용히 사라지고, 승차권은
> 내장 예상값으로 완성된 상태를 유지합니다.
>
> <details><summary>2026-08-03 ~ 08-04 장애 기록</summary>
>
> 게이트웨이 인증은 통과하는데(`X-RateLimit` 헤더 정상) 백엔드가
> `{"resultCode":"01","resultMsg":"serviceKey: 서비스키는 필수입니다."}` 를
> 반환하는 상태가 이틀간 이어졌습니다. 게이트웨이가 `serviceKey` 를 소비한 뒤
> 백엔드로 전달하지 않는 증상이었고, 고속버스정보(15098522)와
> 고속버스도착정보(15098516) 두 데이터셋에서 동일하게 나타났습니다.
> 클라이언트에서 우회할 방법이 없어 오류신고 후 대기했고, 08-05 에 복구되었습니다.
> </details>

## 테스트

배포 전에 실제 브라우저로 동작을 확인합니다.

```
cd tests
npm install     # 처음 한 번 (Chromium 함께 내려받음)
npm test        # 전체 143개, 약 70초
npm run test:data   # 데이터 정합성만, 네트워크 없이 1초
```

TAGO 실제 배차 스위트(27개)는 `TAGO_KEY` 환경변수가 있을 때만 돌아가고,
없으면 건너뜁니다.

목적지·요금 데이터를 손봤다면 전수 점검도 함께 돌리세요. 77곳이 실제로
노선으로 해석되는지 확인합니다(약 2분, `npm test` 에는 포함되지 않음).

```
TAGO_KEY="키" node audit-routes.js
```

목적지·좌표·볼거리를 고쳤을 때는 `npm run test:data` 만으로도 대부분 걸립니다.
자세한 내용은 [tests/README.md](tests/README.md) 를 보세요.

배포 주소: <https://randomtago.netlify.app/>

> 공유 메타(`og:url`, `og:image`)에 위 도메인이 절대 URL로 박혀 있습니다.
> 도메인을 바꾸면 `index.html` 의 `<head>` 에서 함께 수정해 주세요.

## Netlify 배포

1. 이 저장소를 GitHub에 push
2. Netlify에서 **Add new site → Import an existing project** → 저장소 선택
3. 빌드 설정은 비워두면 됩니다 (`netlify.toml`이 publish=`.`, functions 경로를 지정)
4. **Site settings → Environment variables** 에 API 키 등록
   - Key: `TAGO_KEY`
   - Value: 공공데이터포털의 **Encoding(일반 인증키, 인코딩)** 값 권장
     (`%2B`, `%2F`, `%3D` 가 포함된 형태. 게이트웨이는 이 형태를 인식합니다.
     디코딩 키를 넣어도 함수가 `encodedKey()` 로 보정하지만, 인코딩 키가 안전합니다.)
5. 배포 후 함수는 `/api/tago` 로 호출됩니다.

> 키는 서버(함수)에서만 읽고 브라우저로는 절대 내려보내지 않습니다.
> 그래서 프론트 소스에 키가 노출되지 않습니다.

## 프록시 사용법 (`/api/tago`)

- 터미널 목록(디스커버리): `/api/tago?mode=terminals`
- 노선 운행정보(이름→ID 자동 해석):
  `/api/tago?mode=route&depHint=서울경부&arr=목포&date=YYYYMMDD`
- 통과 프록시(원하는 오퍼레이션 직접 호출):
  `/api/tago?op=GetExpBusTrminlList&numOfRows=1000`
- 진단용
  - `?keycheck=1` 환경변수에 키가 들어왔는지(길이·공백 여부만, 값은 노출 안 함)
  - `?debug=1&op=...` TAGO 원본 응답 그대로 보기
  - `?showurl=1` 함수가 만드는 실제 요청 URL 확인
  - `?probe=1` 서비스/오퍼레이션 후보 자동 탐색

현재 살아있는 오퍼레이션은 4종이며 **첫 글자가 대문자**입니다.

```
GetExpBusTrminlList            고속버스 터미널 목록 (terminalNm 부분일치 검색)
GetStrtpntAlocFndExpbusInfo    출/도착지 기반 운행정보
GetExpBusGradList              등급 목록
GetCtyCodeList                 도시코드 목록
```

베이스 URL은 `https://apis.data.go.kr/1613000/ExpBusInfo` 입니다.
구 경로(`ExpBusInfoService/getExpBusTrminlList`)는 폐기되어 `NO_OPENAPI_SERVICE` 를 반환합니다.
다른 오퍼레이션을 통과 프록시로 쓰려면 함수의 `ALLOWED_OPS` 화이트리스트에 추가하세요.

### 터미널 이름·ID 의 함정

노선이 있는데도 "표가 없음"으로 보이는 원인이 대부분 여기 있습니다.
전수 점검은 [`tests/audit-routes.js`](tests/audit-routes.js) 로 합니다.

**같은 이름에 ID 가 여러 개입니다.** 센트럴시티(서울)는 `NAEK020`·`NAEK021` 두 개인데
목포행은 `NAEK020` 에서 0편, `NAEK021` 에서 15편입니다. "전주"는 `NAEK600~604`
다섯 개이고 노선은 `NAEK602` 에만 있습니다. `mode=route` 는 후보 ID 를 순회해
결과가 나오는 조합을 채택하고, 응답의 `tried` 에 확인 내역을 남깁니다.

**괄호 표기 때문에 엉뚱한 정류소가 뽑힐 수 있습니다.** 광주 고속버스터미널은
`광주(유·스퀘어)` 인데, 괄호를 그대로 두고 비교하면 정확일치가 안 되고
"짧을수록 가점" 규칙에 밀려 `광주비아`(비아동 정류소)가 이깁니다.
지금은 괄호 안을 떼고 비교합니다. `_수수료`(정산용 더미)와 `시외` 항목은 제외합니다.

**TAGO 표기가 우리 표기와 다른 곳이 있습니다.** `index.html` 의 `TAGO_ARR` 에
보정을 둡니다.

```
동송     → 철원      동송읍 터미널이 TAGO 에는 "철원"(NAEK148). 신철원은 갈말읍의 별개 터미널
부산서부  → 부산사상   소재지 이름으로 등록됨(NAEK703)
```

**호출을 줄이려면 ID 를 고정합니다.** `depId`·`arrId` 를 주면 이름 검색과 조합
시도를 건너뜁니다. 프론트엔드는 출발지를 `NAEK010`(경부)·`NAEK021`(호남)로
고정해 두어 대부분 1회 호출로 끝납니다. 형식이 잘못된 값은 무시하고 이름
검색으로 넘어갑니다.

> **`depPlandTime` 은 숫자로 옵니다**(`202608050600`). 프록시가 문자열로
> 정규화해서 내려보냅니다 — 숫자에는 `.length` 도 `localeCompare` 도 없어
> 프론트엔드에서 시각 표시와 정렬이 깨집니다.

## 참고

경부·영동선 + 호남선(센트럴시티) 총 77개 대표 노선의 우등 기준 편도
예상 요금·소요시간을 내장했습니다. 실제 출발편·잔여석은 코버스(kobus.co.kr)에서
확인하세요. TAGO API는 배차·요금 정보를 제공하며, 실시간 잔여석·예매는 포함되지 않습니다.

날씨 조회용 좌표는 `index.html` 의 `COORD` 에 `[위도, 경도]` 로 들어 있습니다.
같은 목적지는 30분간 캐시하며, 좌표가 없는 목적지는 날씨 줄을 표시하지 않습니다.
추천 문구는 `weatherTip()` 이 날씨 코드·기온·강수확률과 `SEASIDE`(바다를 낀
목적지 29곳)를 조합해 만듭니다. 필터 4종은 브라우저에 저장하지만
**비 안 오는 곳만은 저장하지 않습니다** — 날씨는 계속 바뀌므로 들어올 때마다
새로 판단하는 편이 맞습니다.

볼거리 데이터는 `index.html` 의 `SPOTS` 객체에 목적지명을 키로 두고
`[이름, 한줄설명, 분류]` 형태로 들어 있습니다. 지도 검색어는 읍·면 단위 터미널명을
`SEARCH_CITY` 로 시·군 이름으로 바꿔서 만듭니다(예: 운천 → 포천).
키가 없는 목적지는 자동으로 지도 검색 카드(관광지·맛집·카페·전통시장)로 대체됩니다.
